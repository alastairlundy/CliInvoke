## Goal

Replace the `lunet init` placeholder landing page at `site/readme.md` with a polished homepage that introduces CliInvoke, explains what it offers, and routes readers to the right documentation by their need. This addresses the landing-page item named in the kickoff and satisfies D001 and D003.

## What to build

The current `site/readme.md` is the default page generated by `lunet init`. It contains a setup checklist for the Lunet static site generator, not an introduction to CliInvoke. Readers landing on the homepage see instructions for editing `config.scriban`, theme variables, and navigation — none of which help them understand or use the library.

Replace the body of `site/readme.md` (preserving the existing front matter) with three explicit blocks that read as a story, not a checklist -

1. **What CliInvoke is** — a concise introduction naming the library, its target audience (.NET developers who need to run external processes), and the problem it solves.
2. **What it offers** — a brief explanation of the three invocation patterns (`CliRun`, `IProcessInvoker`, `IExternalProcess`) and the key capabilities (configuration builders, resource disposal, cross-platform support).
3. **Where to go next** — a routing block that directs readers to the right docs section by their need (beginner, professional developer, power user, or task-based lookup).

Also update `site/config.scriban` so that `site_project_description` is a real description of CliInvoke rather than `"A website built with Lunet."`.

## Recommended Workflow

### Step 1 — Audit existing landing page and config

Where: `site/readme.md`, `site/config.scriban`

- Read the current `site/readme.md` to identify which front-matter fields to preserve and which body content to replace.
- Read `site/config.scriban` to locate `site_project_description`.

Verify: Confirm the front matter (`title`, `layout`, `og_type`) will be preserved and the body is the `lunet init` placeholder.

### Step 2 — Write the "What CliInvoke is" block

Where: `site/readme.md`

- Write a concise opening paragraph naming CliInvoke, its target audience, and the problem it solves.
- Keep it to 2-4 sentences. Avoid jargon not introduced in CONTEXT.md.

Verify: A reader who has never heard of CliInvoke can answer "what does this library do?" from this block alone.

### Step 3 — Write the "What it offers" block

Where: `site/readme.md`

- Briefly describe the three invocation patterns (`CliRun`, `IProcessInvoker`, `IExternalProcess`) and when each is appropriate.
- Mention key capabilities - configuration builders, resource disposal, cross-platform support.
- Keep this block short (a paragraph or a small table). Link to [Choosing your Invocation Pattern](docs/guides/choosing-invocation-pattern.md) for the full treatment.

Verify: The block covers all three patterns without duplicating the detail already in the choosing-invocation-pattern guide.

### Step 4 — Write the "Where to go next" block

Where: `site/readme.md`

- Route readers by need. Use the audience segments already established in `site/docs/readme.md` (beginner, professional developer, power user) or a task-based lookup.
- Each entry should link to the right docs page with a one-line description of what the reader will find there.

Verify: Every link resolves to an existing page. A beginner, a professional developer, and a power user each find a distinct starting point.

### Step 5 — Update site config description

Where: `site/config.scriban`

- Change `site_project_description` from `"A website built with Lunet."` to a real description of CliInvoke (one sentence).

Verify: The description matches the tone and content of the new landing page.

### Step 6 — Build and verify locally

Where: `site/`

- Run `lunet build` (or `lunet serve`) to confirm the new homepage renders without errors.
- Check that the three blocks appear in the correct order and all links resolve.

Verify: The rendered page reads as a story, not a checklist. No broken links.
