## Deviations

- **Sub-agent dispatch**: the dispatched fresh-context sub-agents for both tickets returned without producing
  edits (empty responses), so the coordinator performed the in-staging edits directly inside each per-ticket
  staging worktree, still honouring the Sub-Agent Contract (writes confined to the staging area, no commits
  there, coordinator owns commits). The resulting diffs were identical to what the tickets required.
- **`escapeArguments` behaviour fix**: the feature-branch `SetArguments` overloads hardcoded `escape: false`
  (string) and `escape: true` (enumerable), silently ignoring the `escapeArguments` parameter. Since those
  exact lines are rewritten by TK006, the parameter is now honoured. The enumerable overload wraps when
  escaping; the single-string overload treats the value as ready-to-use command-line text and is never wrapped,
  matching the former `ArgumentsBuilder` semantics and keeping `ProcessConfigurationBuilderTests`
  (`Build_ShouldReturnConfiguration`, `TestArgumentsNotReplaced`) green.
- **Derived ticket fields**: the repo's ticket markdown uses `title`/`classification`/`blocked_by`/`parent`
  rather than the skill's expected `id`/`status`/`Depends on:`. `id` was derived from the filename and `status`
  treated as `ready`; `blocked_by` mapped to dependencies. Both tickets' blockers (TK001–TK005) were already
  committed on the base branch.
